# VodiWalker

پنل فارسی مدیریت کانفیگ‌های VPN، اشتراک‌ها، کاربران، نودها و ربات تلگرام، با FastAPI.

## نصب روی Shiprr

Shiprr برنامه را از **کد منبع** می‌سازد و از `Dockerfile` سفارشی استفاده نمی‌کند. [راهنمای رسمی استقرار Python](https://shiprr.app/guides/deploy-python-app)

1. در [Shiprr → Apps](https://shiprr.app/apps) گزینهٔ **New app** را بزنید و مخزن و شاخه‌ای را انتخاب کنید که این نسخه روی آن push شده است.
2. در **Settings → Build & Runtime** این مقادیر را تنظیم کنید:

   | تنظیم | مقدار |
   | --- | --- |
   | Root directory | `.` |
   | Install command | `pip install -r requirements.txt` |
   | Build command | خالی |
   | Start command | `python app.py` |
   | Health check path | `/healthz` |

   برنامه خودش روی `0.0.0.0` و `PORT` تعیین‌شده توسط Shiprr گوش می‌دهد. تعداد **Replicas** را در **Resources** روی `1` بگذارید؛ نشست‌ها در حافظه‌اند و چند نمونه نباید هم‌زمان در یک دیتابیس بنویسند.
3. در **Settings → Environment variables** از [env.example](env.example) استفاده کنید و نمونه‌ها را با مقادیر خودتان جایگزین کنید:

   | متغیر | توضیح |
   | --- | --- |
   | `ADMIN_USERNAME` | نام کاربری مالک، مثلاً `VodiAdmin` |
   | `ADMIN_PASSWORD` | رمز قوی و یکتا، حداقل ۸ کاراکتر؛ نصب تازه بدون آن شروع نمی‌شود |
   | `SECRET_KEY` | یک مقدار تصادفی مستقل که بین استقرارها ثابت می‌ماند. برای تولید محلی: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
   | `PUBLIC_BASE_URL` | آدرس عمومی واقعی پنل، مانند `https://<app-name>.shiprr.dev`، بدون مسیر |
   | `DATABASE_URL` | آدرس PostgreSQL اختصاصی این پنل برای ماندگاری کاربران و تنظیمات؛ `sslmode=verify-full` پیشنهاد می‌شود |
   | `VW_HTTP_ONLY` | `1`، برای غیرفعال‌کردن شنونده‌های خام TCP و MTProto روی میزبان وب |
   | `KEEPALIVE_ENABLED` | `0`؛ مسیر `/healthz` برای بررسی سلامت کافی است |

4. **Deploy** را بزنید. پس از سالم شدن سرویس، دامنهٔ برنامه را باز کنید و با حساب مالک وارد شوید. برای بررسی اولیه، مسیر `/healthz` باید `200` و متن `pong` برگرداند.

### نکات استقرار و ارتقا

- Shiprr دیسک دائمی ندارد. بدون PostgreSQL پنل بالا می‌آید، اما داده‌های محلی ممکن است با استقرار مجدد از بین بروند. پنل فایل‌ها را به‌صورت دوره‌ای در PostgreSQL ذخیره می‌کند. برای هر پنل از یک دیتابیس جداگانه و پشتیبان منظم استفاده کنید. اگر `DATABASE_URL` تنظیم شود ولی بازیابی ناموفق باشد، پنل برای جلوگیری از بازنویسی داده‌ها شروع نمی‌شود؛ لاگ Runtime و دسترسی شبکه به دیتابیس را بررسی کنید. `sslmode=require` هم در این برنامه گواهی و نام میزبان را بررسی می‌کند.
- اگر نام کاربری یا رمز مالک در محیط تعریف شده باشد، همان متغیر بر مقدار ذخیره‌شده اولویت دارد. برای تغییر آن، متغیر Shiprr را ویرایش کنید. تغییر `SECRET_KEY` هش رمزهای ذخیره‌شده را نامعتبر می‌کند؛ هنگام مهاجرت با کلید جدید، رمز مالک را هم در محیط تنظیم کنید و رمز ادمین‌های فرعی را بازنشانی کنید.
- در حالت `VW_HTTP_ONLY=1` پروکسی خام تلگرام (MTProto/SOCKS5) و دریافت VLESS-TCP خام روی همین سرویس فعال نیستند. این تنظیم ربات تلگرام را غیرفعال نمی‌کند. برای پروتکل‌هایی که به پورت خام نیاز دارند، از سرور جداگانه استفاده کنید. پشتیبانی از هر پروتکل تونل به مسیر شبکه و تنظیمات همان میزبان بستگی دارد.
- برای ارتقا، از داده‌های محیط فعال پشتیبان بگیرید. فایل‌های داده از Git حذف شده‌اند، اما مقادیر نسخه‌های قدیمی همچنان در تاریخچه هستند. اگر کلیدها یا توکن‌های قدیمی استفاده شده‌اند، آن‌ها و لینک پیش‌فرضی را که با کلید قبلی ساخته شده تعویض کنید. فایل `.env` یا پوشهٔ `data/` را به Git اضافه نکنید.

## اجرای محلی و تست

با Python 3.11 یا جدیدتر، وابستگی‌ها را با `python -m pip install -r requirements.txt` نصب کنید. پیش از `python app.py`، متغیرهای محیط را تنظیم کنید؛ برنامه فایل `env.example` را خودکار نمی‌خواند. برای استفادهٔ محلی، آدرس `http://localhost:8000` است و `DATABASE_URL` اختیاری است. `Dockerfile` برای میزبان‌های سازگار با Docker در دسترس است، نه برای Shiprr.

اجرای تست‌های رگرسیون: `python -m unittest discover -s tests -v`.
